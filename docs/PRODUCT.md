# 产品设计

## 用户与任务

面向希望记录猫咪日常、理解相处线索的养猫者。核心过程是“上传画面→结合现场观察→获得互动建议→保存并回看”，而非对单张照片作确定的心理或健康判断。

## 关键产品决策

| 决策 | 目的 | 当前落地 |
| --- | --- | --- |
| 观察与趣味表达分开 | 避免将拟人文案当作事实 | 观察依据、互动建议、趣味猫语分别展示 |
| 今日签图外文案独立保留 | 减少生成图片中乱码对阅读的影响 | 图片与可读文字分离，样例效果已人工确认 |
| 回看复用保存结果 | 避免重复等待和重复费用 | 故事、今日签、塔罗保存后重新读取 |
| 邀请账号独立发放 | 控制演示范围并隔离记录 | 首次改密，不使用所有访客共享的账号 |
| 桌面与手机分别验收 | 宽度模拟不能代替手机操作 | 页面布局检查与真机人工反馈分开 |

## 项目推进方式

以PRD、技术适配、分阶段开发、证据交付和人工验收推进。界面迭代与基础功能复测分别列清单；测试通过、真实模型可用和产品效果被接受分别记录。

本仓库呈现产品决策与可核对实现，不使用未经证实的用户增长、商业收益或团队贡献数字。代码开发使用AI辅助，不将AI生成代码表述为全部手写。
